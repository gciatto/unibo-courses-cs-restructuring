Course design heuristics:
- Size each new course in whole ECTS (the ects field), never above
  $max_ects ECTS. Each proposed topic is worth at least 1 ECTS, so a course may hold
  at most as many topic_keys as its ECTS. Prefer $preferred_ects ECTS: larger
  courses are later considered for splitting into smaller ones.
- Split fat courses, e.g. into a fundamentals course and an advanced course
  that depends on it.
- Split by abstraction level: a generic foundations course (e.g. computation
  and programming fundamentals) plus separate language- or technology-specific
  courses (e.g. C programming, Java programming) that depend on it.
- Split out minimal background for dependent courses: when a course needs
  only the basics of a subject (e.g. a practical statistics course needing
  basic Python but not object orientation or functional programming), make
  those basics a small course of their own rather than requiring the full one.
- The same module may appear in several new courses only when unavoidable;
  prefer prerequisites over duplication.

Requirements:
- proposed_topics contains exactly the topics used by proposed courses.
- proposed_courses assigns one or more proposed topic keys to each new course.
- prerequisites uses prerequisite_course_key -> dependent_course_key semantics
  and must form an acyclic graph.
- Every source topic assigned to a source course must appear in the
  source_topic_keys of at least one proposed topic. Source courses are then
  mapped to proposed courses automatically from this provenance, so no source
  course loses coverage.
- Keys are lowercase snake_case and all references must resolve.
